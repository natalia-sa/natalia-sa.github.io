## Set up inicial com criação da vm

A primeira etapa na jornada de contribuição com o linux é configurar o ambiente de desenvolvimento. Isso foi feito utilizando máquinas virtuais para segregar nosso ambiente real do ambiente de testes e viabilizar o desenvolvimento. 

Para isso, utilizamos o **QEMU**, um emulador para criar a máquina virtual, e o **libvirt**, ferramenta de gerenciamento para essas vms.

Primeiro foi preciso baixar dependências e depois criamos um espaço de trabalho compartilhado no qual nós e o sistema de virtualização poderemos atuar. Um script também foi criado para reunir alguns utilitários importantes para o desenvolvimento

As atividades devem ser executadas com o script ativo, que pode ser feito exeutando a linha abaixo no terminal
```bash
/home/lk_dev/activate.sh
```

Nós baixamos uma imagem do debian para utilizar em nossa VM. Como a imagem citada no tutorial não está mais disponível, foi preciso acessar o site do debian e buscar uma nova imagem semelhante. A imagem tem as seguintes características:

- Distribuição: Debian 12

- Versão: nocloud

- Arquitetura: ARM64 

Também fizemos o resize da imagem para evitar falta de espaço de disco em tarefas futuras.

Após isso extraimos componentes de boot do sistema operacional para que  possamos controlar o processo de inicialização externamente via QEMU. Fazendo uma analogia com um carro, é como se estivessemos tirando o "motor" (Kernel) e a "chave de ignição" (Initrd) de dentro do carro (imagem do disco) para guardá-los onde poderemos trocá-los depois.


Com isso, foi possível criar nossa vm com o QEMU
```bash
launch_vm_qemu
```

o usuário para login é root, sem uso de senha.
Podemos sair da vm digitando:
```bash
poweroff
``` 

Ao reiniciar nossa máquina host precisamos executar para conseguir usar os serviços:
```bash
sudo systemctl start libvirtd # starts the libvirt daemon
systemctl status libvirtd # shows the status of the daemon
sudo virsh net-start default # starts `virsh` default network
sudo virsh net-list
``` 

A partir daqui paramos de usar o QEMU para criar a vm e passamos a usar o libvirt para isso.
O libvirt é um serviço que roda em background. Ele permite:

- Persistência: A VM pode rodar sem um terminal aberto.

- Rede Simplificada: Ele cria automaticamente uma ponte de rede (virbr0) para que sua VM tenha internet e você consiga se comunicar com ela facilmente.

**Outros comandos úteis do `virsh`**

O `virsh` é a interface de linha de comando principal para gerenciar máquinas virtuais via libvirt. Abaixo estão os comandos mais comuns para manipular a VM `arm64`:

| Objetivo | Comando |
| :--- | :--- |
| Listar todas as VMs | `sudo virsh list --all` |
| Ver informações da VM | `sudo virsh dominfo arm64` |
| Iniciar com console | `sudo virsh start --console arm64` |
| Desligamento seguro | `sudo virsh shutdown arm64` |
| Forçar desligamento | `sudo virsh destroy arm64` |
| Remover registro da VM | `sudo virsh undefine arm64` |

## Conexão com a vm via ssh

Como a imagem utilizada na vm não possuia suporte a ssh, foi necessário instalá-lo. Também foram feitas algumas alterações para permitir a conexão sem senha e por root login

Podemos encontrar o ip da vm com o comando abaixo:

sudo virsh net-dhcp-leases default
```bash
sudo virsh net-dhcp-leases default
``` 

E com esse dado podemos nos conectar via ssh com nossa vm:

```bash
ssh root@<VM-IP-address>
``` 

Por fim, guardamos a lista de módulos kernel que temos carregados na vm para atividades futuras num arquivo de nome `vm_mod_list`
