## O Kworkflow

Este é mais um software que nos auxiliará a realizar nossas atividades relacionadas ao desenvolvimento do kernel.

Para isntalá-lo fizemos o clone de seu repostório e utilizamos o comando abaixo:
```bash
./setup.sh --full-installation
```

Para futuras atualizações do kw podemos utilizar: 
```bash
kw self-update # updates na master
kw self-update --unstable # updates na branch unstable
kw --version # para checar sua versão
```

Existem múltiplos subsistemas do kernel linux e utilizaremos o IIO para nossas atividades. Eles também são chamados kernel trees. 

Com o kw podemos criar condifurações locais para o nosso kernel (ele funciona de modo semelhante ao git)

Para incializar uma config utilizamos
```bash
cd "$IIO_TREE" # go to the IIO tree directory
kw init # initialize local configurations for the IIO tree
```

Podemos configurar o kw para facilitar o acesso via ssh a nossa vm
```bash
cd "$IIO_TREE"
kw remote --add arm64 root@<VM-IP-address> --set-default
kw ssh
```

## Configurando a compilação do kernel

O kernel build system (kbuild) usa arquivos .config como configuração e existem .config pré-configuados para algumas arquiteturas. Assim, setamos nossa config para o tipo de arquitetura que estamos utilizando, que é a arm64. Algumas outras configs também foram necessárias devido ao fato de que estamos fazendo cross compilation.

Para compilar o kernel utilzamos: 
```bash
kw build
```

Instalamos os módulos na vm: 
```bash
kw deploy --modules 
```

e atualizamos nosso script de activate para apontar para o novo kernel.

Após isso, recriamos nossa vm com as novas configurações.

Podemos checar qual kernel estamos usando entrando na vm e executando:
```bash
uname --kernel-release
```
