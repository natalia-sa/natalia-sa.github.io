## The Patch

In this post, I will describe the end-to-end process of contributing to the Linux kernel, specifically focusing on the **IIO (Industrial I/O)** subsystem.

### 1. Cloning the Correct Tree

Since I was already working on tutorials using the IIO tree, it was not necessary to clone it again. However, as my previous work was done on a testing branch, the first step was to ensure a clean workspace. 

I moved my previous experiments to a dedicated backup branch to preserve them, and then performed a checkout to the official development branch: **`togreg`**. You can find authoritative information about kernel trees and branches in the [MAINTAINERS file](https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/tree/MAINTAINERS).

#### Managing Branches

First, I created a backup of my current progress:
`git branch tutoriais-backup`

Then, I needed to ensure my local `togreg` branch was correctly tracking the remote repository. It was necessary to set the upstream locally:

```bash
git branch --set-upstream-to=origin/togreg togreg

## check if they point to the same commit
git rev-parse togreg
git rev-parse origin/togreg
```

Then we created our work branch:

```bash
git checkout -b iio-deduplicate-code
```

The code duplications targeted for refactoring were identified across several drivers within the IIO HID subsystem. Specifically, the following six functions—each consisting of 9 lines of identical logic—were selected for deduplication:

Function find: accel/hid-sensor-accel-3d.c::accel_3d_adjust_channel_bit_mask, TOTAL NUMBER LINES IN FUNCTION: 9
Function find: pressure/hid-sensor-press.c::press_adjust_channel_bit_mask, TOTAL NUMBER LINES IN FUNCTION: 9
Function find: magnetometer/hid-sensor-magn-3d.c::magn_3d_adjust_channel_bit_mask, TOTAL NUMBER LINES IN FUNCTION: 9
Function find: light/hid-sensor-prox.c::prox_adjust_channel_bit_mask, TOTAL NUMBER LINES IN FUNCTION: 9
Function find: light/hid-sensor-als.c::als_adjust_channel_bit_mask, TOTAL NUMBER LINES IN FUNCTION: 9
Function find: gyro/hid-sensor-gyro-3d.c::gyro_3d_adjust_channel_bit_mask, TOTAL NUMBER LINES IN FUNCTION: 9

To begin the refactoring process, let's open these files in VS Code.

```bash
code drivers/iio/accel/hid-sensor-accel-3d.c \
     drivers/iio/pressure/hid-sensor-press.c \
     drivers/iio/magnetometer/hid-sensor-magn-3d.c \
     drivers/iio/light/hid-sensor-prox.c \
     drivers/iio/light/hid-sensor-als.c \
     drivers/iio/gyro/hid-sensor-gyro-3d.c
```

All of them share the exact same function, with only the function name being different:

```c
static void magn_3d_adjust_channel_bit_mask(struct iio_chan_spec *channels,
						int channel, int size)
{
	channels[channel].scan_type.sign = 's';
	/* Real storage bits will change based on the report desc. */
	channels[channel].scan_type.realbits = size * 8;
	/* Maximum size of a sample to capture is u32 */
	channels[channel].scan_type.storagebits = sizeof(u32) * 8;
}
```

Let's design a generic version of this function, since each file uses a different naming:

```c
static void hid_sensor_adjust_channel_bit_mask(struct iio_chan_spec *channels,
						int channel, int size)
{
	channels[channel].scan_type.sign = 's';
	/* Real storage bits will change based on the report desc. */
	channels[channel].scan_type.realbits = size * 8;
	/* Maximum size of a sample to capture is u32 */
	channels[channel].scan_type.storagebits = sizeof(u32) * 8;
}
```

### Choosing the location for our generic function

Since the code was identical across multiple drivers, I had to move it to a shared location. In the IIO HID subsystem, the most suitable place is `drivers/iio/common/hid-sensors/hid-sensor-attributes.c`, as it already manages shared attributes and formatting logic for these sensors.

I also exported the symbol using `EXPORT_SYMBOL_NS` to ensure that drivers compiled as loadable modules can access this function at runtime.

In `drivers/iio/common/hid-sensors/hid-sensor-attributes.c`, we place our generic function at the end of the file

```c
void hid_sensor_adjust_channel_bit_mask(struct iio_chan_spec *channels,
					int channel, int size)
{
	channels[channel].scan_type.sign = 's';
	/* Real storage bits will change based on the report desc. */
	channels[channel].scan_type.realbits = size * 8;
	/* Maximum size of a sample to capture is u32 */
	channels[channel].scan_type.storagebits = sizeof(u32) * 8;
}
EXPORT_SYMBOL_NS(hid_sensor_adjust_channel_bit_mask, "IIO_HID");
```

In addition to modifying this file, we will also update a header file: `include/linux/hid-sensor-hub.h`

```c
void hid_sensor_adjust_channel_bit_mask(struct iio_chan_spec *channels,
					int channel, int size);
```

We have removed the local functions from all six files and replaced their calls with our new generic function.
